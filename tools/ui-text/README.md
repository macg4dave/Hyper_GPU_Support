# UI text validator

Locale-root loading is shared with the product build. Run `cargo run --locked --manifest-path tools/ui-text/standalone/Cargo.toml -- resources/i18n --locale en-GB` to validate all complete catalogues and select one. Only `en-GB` currently exists. Unknown requested tags fall back to `en-GB`; malformed or incomplete installed catalogues fail validation. `--generate` in this mode emits the resolved Rust/Slint locale metadata too. Existing single-directory commands below retain British English validation. See [the locale architecture and future translation workflow](../../docs/UI_TEXT_GUIDE.md#internationalisation-architecture).

Independent contributor crate for LANG-007. It has no product, Slint or Windows-backend dependency. Its isolated lockfile uses the root lockfile's resolved Serde/TOML versions and dependency closure. LANG-004 now uses the shared library as a root build dependency; no runtime loader is added. The standalone manifest at `standalone/Cargo.toml` has its own workspace/lockfile and reuses `../src` and `../tests` directly, without a product dependency. The root library package participates in the product workspace; the root default member stays the product. This avoids nested workspace-root conflicts while retaining one implementation.

Run from the repository root:

```powershell
cargo test --locked --manifest-path tools/ui-text/standalone/Cargo.toml
cargo run --locked --manifest-path tools/ui-text/standalone/Cargo.toml -- resources/i18n/en-GB
cargo run --locked --manifest-path tools/ui-text/standalone/Cargo.toml -- resources/i18n/en-GB --generate local/evidence/ui-text-generated
python -B scripts/testing/test_check_ui_copy.py
python -B scripts/testing/check-ui-copy.py --json
```

Add `--offline` to Cargo commands when the pinned dependencies are cached. Resource input is read at execution time: invalid catalogues do not prevent compiling the validator. A failed check returns nonzero and never constructs a partially validated catalogue. CLI generation validates the whole set before creating output. Outputs must be outside the resource tree and are rewritten only when bytes differ. Existing generated files are not a fallback after a failed check; build callers must propagate the error.

[contract.rs](src/contract.rs) and its included [fixed](src/fixed-contract.toml)/[dynamic](src/dynamic-contract.toml) tables form the independent developer-owned active contract, without resource wording. The current product has 408 active keys across ten feature files; [reconciliation](../../tests/fixtures/ui-text/migration.json) records 288 pending keys. The original nine-key [fixture](../../tests/fixtures/ui-text/validator/baseline) is preserved as historical comparison data, not valid standalone input for the expanded active set. Isolated failure tests now use the full product resources. Pending keys are rejected as unknown until their reviewed batch activates them.

The locale-root CLI and `build.rs` use `locales::load(root, requested, contract)` and `LoadedCatalogue::generate()`. The British English single-directory CLI retains `validate_directory(path, contract)` and `Catalogue::generate()`; both use the same locale-independent validator/generator. Validation covers strict UTF-8/schema, exact metadata, owning files/keys, template grammar, types/occurrences, generated name conflicts and native UTF-16 budgets including termination. Only validated catalogues can generate sources. Generation uses parsed segments and contract argument order, preserves decoded text, escapes Rust/Slint separately, and inserts arguments as data. It returns deterministic UTF-8/LF source bytes; the build adapter tracks directory membership, required files and tool sources, and publishes only validated output in `OUT_DIR`.

The copy scan covers 28 paths, enforces absence of active hard-coded copy and lists remaining lexical candidates as advisory. [Its reviewed policy](../../tests/fixtures/ui-text/validator/copy-scan.json) records each path's extraction boundary and exact retained-input/helper exceptions with reasons. Exceptions cannot permit a different string or source path. Rust test modules and test fixtures are excluded. Lexical scanning is not a Rust/Slint parser, secret detector or complete coverage proof; reconcile the inventory separately.

Generated fixed constants and accessors share the same validated text. Four Slint compositions use public pure functions emitting already-parsed literal/parameter segments; no runtime parser or recursive expansion is introduced. Their existing model-length/string inputs retain their types. `u64` function arguments are rejected to prevent narrowing; Rust accessors retain numeric widths. Headless tests compare these functions with resource segments, adversarial data and Rust count output. Rendering remains untested.

Focused tests use synthetic edits, local temporary files, CLI subprocesses and a temporary Windows directory junction (or Unix symlink) to exercise rejection without reading its target. No native prompt, GUI launch, guest, VM, GPU, driver, protected runner or actual vault operation is used. LANG-004 now proves generated compilation, two headless window defaults and TOML-only rebuild propagation for the representative subset. The explicit resource-mutating proof is `python -B scripts/testing/test-ui-text-rebuild.py`; it restores original bytes in `finally`. Rendered/editor acceptance remains later work.
