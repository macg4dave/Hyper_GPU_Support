# HV-003 installed management and privilege contract

## Scope

- Observed 2026-09-25 on Windows 11 Pro 25H2 build `26200.9457`, x64.
- Hyper-V PowerShell module `2.0.0.0`; HCS/SDK versions are listed below.
- Read-only inspection only. No adapter add/set/remove, partition-count change,
  HCS call, VM operation or host/guest mutation was performed.
- HV-001's explicitly approved administrator query established one GPU-P
  interface and zero registered VMs. This task did not broaden or repeat that
  authorization.

## Installed GPU-P management surface

All four per-VM cmdlets are installed at module version `2.0.0.0`.

| Cmdlet | Target parameter sets | Selection and resource parameters |
|---|---|---|
| `Add-VMGpuPartitionAdapter` | mandatory `-VMName String[]` or `-VM VirtualMachine[]` | optional `-InstancePath String`; optional `UInt64` min/max/optimal VRAM, encode, decode and compute fields |
| `Get-VMGpuPartitionAdapter` | mandatory `-VMName String[]` or `-VM VirtualMachine[]` | optional `-AdapterId String` |
| `Set-VMGpuPartitionAdapter` | mandatory `-VMName`, `-VM`, or piped `-VMGpuPartitionAdapter` | optional `-AdapterId`; optional `UInt64` min/max/optimal VRAM, encode, decode and compute fields |
| `Remove-VMGpuPartitionAdapter` | mandatory `-VMName`, `-VM`, or piped `-VMGpuPartitionAdapter` | optional `-AdapterId`; supports `-WhatIf`/`-Confirm` |

`Get-VMHostPartitionableGpu` is installed with optional `-Name String` plus
remote-session parameters. The explicit physical-GPU selection syntax for an add
is therefore the exact interface returned as `Name` by the host query/WMI and
passed through `Add-VMGpuPartitionAdapter -InstancePath <interface>`. The current
RTX interface is recorded in [HV-001](HV-001.md#gpu-and-driver). A friendly model
name or enumeration order is not an acceptable substitute.

`Set-VMHostPartitionableGpuPartitionCount` is **absent** from the installed
module. The observed partition count was not changed.

## Rights and state contract

| Operation | Normal medium token | Approved administrator evidence | Mutation/state rule |
|---|---|---|---|
| Read WMI class metadata | allowed | not needed | read-only |
| Read `Msvm_PartitionableGpu` instances/ranges | allowed | not needed | read-only |
| Read `Msvm_GpuPartitionSettingData` instances | allowed; zero rows | not needed | read-only |
| `Get-VMHostPartitionableGpu` | denied (`AccessDenied` in nested Hyper-V exception) | allowed in HV-001 | read-only |
| `Get-VM` | denied (`AccessDenied`) | allowed in HV-001; zero VMs | read-only |
| `Get-VMGpuPartitionAdapter` | no target exists; not invoked | no target exists | read-only, exact VM required |
| Add/set/remove VM GPU adapter | not invoked | not authorized or invoked | protected mutation; exact enrolled disposable VM and GPU required |
| Change host partition count | cmdlet absent; not invoked | not invoked | excluded from current path |
| HCS enumerate/open/get | not invoked | not invoked | rights and object visibility unmeasured |
| HCS create/modify/start/stop/terminate | not invoked | not invoked | protected mutation; unavailable to project until a bounded comparison is justified |

The installed cmdlet metadata and local help do not state a reliable running/off
VM matrix for add/set/remove. With no VM, this task cannot measure it. CORE-005
must fail closed unless its later adapter has an explicitly tested state; GPU-011
owns lifecycle-state experiments. No live/saved/checkpoint state is presumed safe.

Host mutation rights are intentionally not inferred from the successful
administrator read query. HV-002/CORE-005 must determine whether a dedicated
Hyper-V Administrators principal suffices for each fixed operation before any
runner installation or mutation request. Guest rights are not applicable to these
host adapter cmdlets; later guest staging and PowerShell Direct require separate
guest credentials/integration evidence.

## Exact unresolved experiments

1. Create or identify the authorized Generation 2 disposable VM from the immutable
   parent workflow; none is registered now.
2. On that disposable target, measure add/get/set/remove behavior in each required
   stopped/running/restart state without testing saved/checkpoint paths by default.
3. Determine the minimum principal/ACL for each fixed operation, including whether
   Hyper-V Administrators is sufficient without a full administrator token.
4. Verify an added adapter's `AdapterId`, `HostResource`/interface and effective
   resource values through both cmdlet and WMI views.
5. Compare HCS only if the native VMMS path reproduces a specific essential
   failure; retain identical GPU, runtime, guest and workload inputs.

These are planned experiments, not current blockers. They require a concrete
disposable target and separately scoped protected-operation authorization.
