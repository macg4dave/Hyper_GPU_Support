## Commands run

The following command families were run from Windows PowerShell 5.1. Host/PnP
queries ran without elevation. After explicit user approval, the Hyper-V GPU,
supported-version and VM/per-VM query families ran in an administrator process.

```powershell
Get-ComputerInfo -Property WindowsProductName,WindowsEditionId,WindowsVersion,
  OsName,OsVersion,OsBuildNumber,OsArchitecture,CsSystemType,CsHypervisorPresent
Get-ItemProperty 'HKLM:\SOFTWARE\Microsoft\Windows NT\CurrentVersion'
Get-CimInstance Win32_Processor
Get-CimInstance Win32_OptionalFeature
Get-CimInstance Win32_Service
Get-Module -ListAvailable Hyper-V
Get-Command Get-VMHostPartitionableGpu,Get-VMGpuPartitionAdapter,
  Add-VMGpuPartitionAdapter,Set-VMGpuPartitionAdapter,Remove-VMGpuPartitionAdapter
Get-VMHostPartitionableGpu
Get-CimInstance Win32_VideoController
Get-CimInstance Win32_PnPSignedDriver
Get-PnpDeviceProperty -InstanceId <redacted RTX device instance>
pnputil.exe /enum-devices /class Display /drivers
pnputil.exe /enum-drivers /class Display /files
nvidia-smi.exe --query-gpu=name,pci.device_id,pci.bus_id,driver_version,memory.total --format=csv,noheader
Get-VM
Get-VMHostSupportedVersion
Get-CimInstance -Namespace root/virtualization/v2 -ClassName Msvm_ComputerSystem
Confirm-SecureBootUEFI
Test-Path <CBS and Windows Update reboot marker keys>
Get-ItemProperty <Session Manager pending-file-rename value>
```

The administrator process verified its elevated token and returned no `Get-VM`
rows, so the per-VM firmware, security, processor, memory, disk, GPU-adapter and
guest-KVP loops performed no target operations.
