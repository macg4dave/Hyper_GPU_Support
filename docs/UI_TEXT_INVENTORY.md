# UI text inventory

LANG-001 static audit, 13 October 2026. Scope and sequence are owned by the [roadmap](roadmap.md); task status is owned by the [backlog](backlog.md). This records the existing wording and consumers, without changing product source or wording. It is not a catalogue, a compiled baseline or visual evidence.

The [occurrence register](UI_TEXT_OCCURRENCES.md) records 1,404 source string occurrences across 29 producer files, grouped into 1,182 rows. Each row retains source lines, original source template, producer/component, parameters, proposed key family, batch and disposition. Repeated literals retain every location. Read the consumer/branch map below with those rows: a formatting fragment or classifier input is not automatically a standalone catalogue entry. The scan seeds the register; consumer tracing determines its scope and exceptions.

Snapshot: commit `6199ac18753c020660a52e994c1d805d054d7f1b`, with the user's documentation/tooling changes already present. The occurrence register includes SHA-256 fingerprints of inspected producer files. No product source was modified for this audit. Line links refer to that source snapshot and must be reconciled when migration changes it.

## Dispositions and extraction batches

| Class | Disposition | Resolution / exception reason |
|---|---|---|
| C | Application-owned copy | Extract verbatim, including app-owned technical-detail prose and native explanations. Keep field values separate from the template |
| M | Copy mixed with immutable input | Preserve the original dispatch/classification/progress input. LANG-013 separates that identity from presentation before LANG-004/006 makes the displayed equivalent editable |
| P | Immutable control/protocol/schema input | Retain action/dialog tokens, vault identities, JSON/WMI names, failure envelopes and classifier needles. A human-readable equivalent still belongs in C/M; this is not a blanket diagnostics exception |
| F | Code-owned formatting or empty sentinel | Retain exact numeric conversion, separators and empty-state logic. Put surrounding prose in the catalogue. Any future change to unit rendering first removes display parsing and passes byte/output baselines |
| X | Non-copy or unconnected helper | Imports, fonts, assets and helpers with no production GUI call site are outside this migration; the exception list below identifies them. Reassess helpers if they become connected |
| D | External data, documented separately below | Insert names/paths/numbers once as data. Keep existing filtering and redaction; do not make untrusted error output a formatting parameter |

| Batch | Features | Cards / constraints |
|---|---|---|
| B1 | Window/navigation, cards, pages, details, resource controls, dialogs, accessibility and default properties | LANG-005, including invisible/disabled/default branches; power/status controls require LANG-013 first |
| B2 | State/draft/availability, Apply/enrollment/Verify/repair/removal/deletion/recovery reviews and results | LANG-006; preserve typed plans, admission, hold state, final-power policy and save-only |
| B3 | Worker stages, transfer counters, progress log/current stage/step list | LANG-013 then LANG-006; fixed wire strings remain immutable and counters are derived before editable formatting |
| B4 | Reporting summaries, inventory/capability explanations and technical-detail prose | LANG-006; classify and redact first; retain diagnostic code namespaces and schema identities |
| B5 | Native sign-in captions/explanations and credential results | LANG-004 representative integration, then LANG-006; preserve local prompts, cancellation and opt-in storage |

Keys in the register are historical proposals within semantic families, with temporary variant numbers rather than final identifiers. The [LANG-003 baseline](UI_TEXT_BASELINE.md) now assigns stable meaning-specific display keys and named parameters under the [LANG-002 guide](UI_TEXT_GUIDE.md), merging only equivalent contexts and retaining original control inputs. No runtime catalogue or generated accessors exist yet. Default/override duplicates need one wording contract only when their meanings really agree.

## Coverage limits and next decisions

The audit covers all production Slint components and all Rust GUI modules, then traces connected library presentation, progress, native credential, capability and redaction producers. Production literals include hidden/default branches; comments/test fixtures and asset file contents are not catalogue messages. Every registered producer has a disposition; external data and unconnected helpers have the reasons above. Lexical counts are inventory bookkeeping, not a proof of complete runtime rendering or path reachability.
